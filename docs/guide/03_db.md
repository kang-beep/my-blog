## 테이블 요약

`schema.md`와 동일. 핵심만:

### `posts`

- `like_count` (int, default 0) — `post_likes` 트리거로 동기화
- `excerpt` nullable — `null`이면 프론트에서 본문 기반 자동 미리보기
- `image_url` — 목록 썸네일 전용 (상세 hero 미사용)
- `category` NOT NULL — 에디터에서 미선택 시 **`기타`** 로 자동 저장
- `category_id` FK → `categories`

### `post_likes`

- `post_id` FK → `posts` **ON DELETE CASCADE**
- `visitor_key` — 브라우저 `localStorage` UUID
- UNIQUE `(post_id, visitor_key)`
- anon/authenticated: select, insert, delete (익명 좋아요·취소)

### `tag_stats` / `tag_edges`

- 관리자 글 create / update / delete 후 `refreshTagStats()`로 전체 재집계

### 카테고리

- `deleteCategory`: 해당 글은 **`기타`** 로 이동 (글 삭제 없음)
- **`기타` 카테고리는 삭제 불가** (`bootstrap.sql` 시드)

### 글 삭제

- 앱: Storage → Giscus Edge Function → `posts` DELETE
- DB: `post_likes`는 CASCADE로 자동 삭제
- 상세: [`06_post_delete_and_giscus.md`](./06_post_delete_and_giscus.md)

## GRANT + RLS

`bootstrap.sql`에 포함. RLS만 켜고 `GRANT`가 없으면 `42501 permission denied` 발생.

### 외부 피드 테이블

- anon/authenticated: **SELECT only**
- INSERT/DELETE: GitHub Actions (`service_role`)

## Storage 버킷

| 버킷 | 용도 | 경로 패턴 |
|------|------|-----------|
| `posts-images` | 글 썸네일·본문 이미지 | `{postId}/…`, `{postId}/content/…` |
| `avatars` | 프로필 아바타 | `{uuid}.{ext}` |
| `portfolio-images` | 포트폴리오 이미지 | TBD |

정책: public read, 업로드·수정·삭제는 `authenticated` (`bootstrap.sql`).

글 삭제 시 `posts-images/{postId}/` 하위 파일은 앱에서 일괄 삭제 (`postStorageCleanup.js`).

## 트러블슈팅

| 증상 | 조치 |
|------|------|
| `schema cache` / 테이블 없음 | `bootstrap.sql` 실행 후 재시도 |
| `permission denied` / 42501 | `bootstrap.sql`의 GRANT·RLS 확인 |
| Storage 업로드 실패 | 버킷 생성·정책·MIME(WebP) 확인 |
| Actions ping 실패 | `service_role`에 `posts` SELECT 부여 (`bootstrap.sql` 포함) |
| 글 삭제 후 이미지·댓글 잔존 | [`06_post_delete_and_giscus.md`](./06_post_delete_and_giscus.md) |
| 클라이언트 환경변수 누락 | `.env.local` / Vercel `VITE_*` 확인 |
